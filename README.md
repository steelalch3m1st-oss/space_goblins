# Космічна зміна: Форпост

Браузерна гра для NASA Space Apps Challenge Kyiv 2026 — «Build a Junior
Astronaut Mission Trainer». Гравець планує день астронавта (МКС, Apollo на
Місяці, CHAPEA/Jezero на Марсі), запускає симуляцію і бачить наслідки своїх
рішень у вигляді коміксу, балів і досягнень.

## Стек

Один самодостатній HTML-файл: vanilla JavaScript, без збірки, без бекенду.
Залежностей для встановлення немає.

Дві зовнішні мережеві залежності завантажуються в рантаймі з CDN:
- `fonts.googleapis.com` — шрифти Handjet і Press Start 2P (піксельний стиль).
- `cdnjs.cloudflare.com` — Sortable.js (перетягування завдань у плануванні).

Якщо інтернету немає, гра все одно працює: шрифти відкочуються на
системний моноширинний, а завдання в план можна додавати кліком навіть
без Sortable.js. Для хакатону без надійного Wi-Fi варто завантажити ці
два файли заздалегідь і підключити локально (`<link>`/`<script src>` на
локальний шлях замість CDN-URL).

## Запуск локально

Файл можна відкрити подвійним кліком, але краще через локальний сервер
(деякі браузери інакше неправильно визначають кодування):

```bash
python3 -m http.server 8000
# або: npx serve .
```

Відкрити в браузері: **http://localhost:8000/**

## Як грати (основний цикл)

1. Головний екран → обрати локацію (МКС / Місяць / Марс).
2. Обрати місію-сценарій (легку чи складну) → «Почати місію».
3. Прочитати брифінг від ЦУП (можна озвучити голосом або показати все одразу).
4. У «Плануванні» додати завдання у розклад дня, зважаючи на залежності
   («Спершу: …»), дедлайни («Тільки до: …») і вікна зв'язку.
5. «Запустити день» → симуляція програє план кадр за кадром коміксом.
   Міні-ігри (+40 балів кожна) можна пройти або пропустити без штрафу.
6. Помилка в порядку/часі → «ЗЛАМ!», день не зарахований, хід переходить
   до наступного гравця з того самого дня (кооперативна механіка).
7. Успіх → вікно результатів: бали, досягнення, новий факт NASA із
   джерелом → «Наступний день».

## Збереження прогресу

Досягнення, відкриті факти та базовий прогрес по місіях зберігаються в
`localStorage` браузера (ключі `kz-ach`, `kz-facts`, `kz-miss`,
`kz-worlds`, `kz-seen`) і переживають перезавантаження сторінки.

**Відоме обмеження:** позиція всередині поточної місії (на якому саме дні
з чотирьох/п'яти ви зупинились, поточний чернетковий план) НЕ зберігається
між перезавантаженнями — перезавантаження сторінки повертає на головний
екран, і місію потрібно починати з дня 1. Залишено як відому прогалину
свідомо: виправлення вимагає нового коду збереження стану місії, що
виходить за рамки поточної задачі «працездатна інтегрована версія без
нових механік».

## Що інтегровано в цій збірці

- **25 днів, 7 місій** (МКС ×2, Apollo ×3, CHAPEA/Jezero ×2) — засновані
  на зонно-графовому рушії з перевіркою прохідності (Floyd-Warshall).
- **42 досягнення**, кожне верифіковане автоматичним тестом як досяжне
  і не автоматичне (`tests/achievements.test.js`).
- **Частковий залік дня** («soft»-завдання: можна пропустити конкретні
  необов'язкові-по-суті кроки без провалу всього дня, з −50% балів).
- **Піксельний чорно-білий візуальний стиль** за гайдом
  «Піксельний місяць» (Handjet + Press Start 2P, дизер Баєра).
- **3 міні-ігри** (протри панелі від пилу, наведи сонячну панель, збери
  розсипаний кадр) — прив'язані до конкретних завдань у кожній з 7 місій.
- **Кооперативний режим кількох гравців**: провал дня передає хід
  наступному гравцю з того самого місця.

## Відомі обмеження

- Позиція всередині місії не зберігається між перезавантаженнями
  (див. вище «Збереження прогресу»).
- Без інтернету піксельні шрифти й перетягування завдань мишею
  недоступні (є робочий запасний варіант — див. «Стек» вище).
- Кілька міні-ігор (наприклад «Вежа до Сонця») використовують один і той
  самий текст-факт на різних завданнях різних місій (МКС і Місяць) — у
  рідкісних випадках фактологічний текст наприкінці міні-гри не точно
  відповідає сюжетному контексту конкретного завдання. Це не впливає на
  проходження чи бали, лише на точність супровідного тексту.
- `docs/DATA_SOURCES.md` фіксує, які факти гри підтверджені прямим
  доступом до офіційних джерел NASA/CSA, а які — ні (мережеві обмеження
  середовища розробки). Рекомендовані подальші кроки для команди — там
  само, розділ 6.

## Структура репозиторію

```
index.html              — гра (відкривати цей файл)
docs/                    — дизайн-документи команди
  MISSIONS_v1.md, MISSIONS_v2.md, MISSION_FEATURES.md
  ACHIEVEMENTS_v1.md, SCORING_v1.md
  DAYS_AND_ACHIEVEMENTS_v1.md   — журнал правок балансу й механік
  DATA_SOURCES.md               — аудит відповідності офіційним даним NASA/CSA
tests/                   — автоматичні перевірки рушія (Node.js, без залежностей)
  passability.test.js, achievements.test.js, partial-pass.test.js
  extract-engine.js, solvelib.js — спільна інфраструктура тестів
```

## Подальша робота для команди

- Відновлення позиції в місії після перезавантаження сторінки (повне
  збереження стану, а не лише ачівок/фактів).
- Вичитати та за потреби виправити текст-факти міні-ігор, прив'язаних
  до кількох різних місій (див. «Відомі обмеження»).
- За бажання — вендорити Google Fonts і Sortable.js локально для повної
  офлайн-роботи на самому хакатоні.
- `docs/DATA_SOURCES.md`, розділ 6: 2–3 запропоновані MVP-інтеграції
  реальних даних NASA/CSA (текстові правки, без зміни механік).
