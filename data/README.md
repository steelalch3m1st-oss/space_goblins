Дані NASA у грі лежать у `index.html` (константа `NASA_DATA`). Усі записи мають `verify:true`: їх внесено вручну з відкритих публікацій і з уже наявного тексту гри.
Живий запит до api.nasa.gov під час розробки повернув 404, браузер їх не викликає.

Повний ланцюжок «NASA-джерело → науковий принцип → ігрове правило → що засвоює
дитина» для трьох активних місій MVP — у `docs/DATA_SOURCES.md`, розділ 0.
Тут — лише короткий статус перевірки кожного запису `NASA_DATA`:

- **flare** (Apollo 11): DONKI FLR, 2024-10-03 (X9.0, AR 3842) — перевірено,
  джерело реальне. Важливо: цей спалах стався в 2024, а не під час місії
  Apollo 11 (1969) — у грі він поданий як окремий історичний факт про
  небезпеку сонячної активності, а не як подія місії.
- **radiation** (МКС): текст картки — навчальне узагальнення («дозиметри
  МКС вимірюють радіацію постійно»), не конкретне число дози. Спроба взяти
  реальні числа дози з OSDR RadLab API не вдалася: 14.11.2026 усі запити до
  `visualization.osdr.nasa.gov/radlab/gui/data-api/` повертали HTTP 500.
  Ігрова шкала радіації (`RAD` у index.html: ліміти, множники зон, нове
  досягнення `radsafe`) — це коефіцієнт балансу гри, **не вимірювання NASA**;
  ніде в інтерфейсі він не підписаний як реальна доза. Коли RadLab API
  запрацює, значення `absorbed_dose_rate` для МКС можна додати в картку
  `radiation` текстом (з джерелом), без зміни ігрової шкали `RAD`.
- **delay** (CHAPEA): час проходження сигналу Земля-Марс (4–24 хв), джерело
  NASA Science — перевірено. Ігрове правило `gap:{min:40}` (діє з дня 1 для
  `req`→`ans`, і з самого початку для дня 2 `req2`→`ans2`) моделює повний
  цикл запит-відповідь (20 хв туди + 20 хв назад), а не лише одностороннє
  проходження сигналу; 20 хв в один бік — представницьке значення всередині
  реального діапазону, не крайнє й не вивірене під конкретну дату. CHAPEA —
  наземний аналог (Mars Dune Alpha, Х'юстон): затримка там накладається
  штучно, а не виникає фізично, і про це сказано в `docs/DATA_SOURCES.md`.
